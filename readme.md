# Sequence Bridge

A productized-services company selling operating results: we install a proven booking sequence in small practices (dentists first) so every lead becomes a booked appointment that shows up. See [sequence-bridge.md](sequence-bridge.md) for the full business definition.

## Repository structure

One repo, three surfaces, one shared design foundation:

```
sequence bridge/
├── internal/          # steering docs, specs, and the design system
│   └── design/        # design.md, tokens.json, elements/components/sections reference pages
├── marketing/         # the Sequence Bridge marketing site (static, brand theme)
└── app/               # the platform we own and operate
    └── themes/        # per-client token files for tenant landing pages
```

## Design system principles

* **Share the tokens, not the components.** `internal/design/tokens.json` is the single source of truth for colors, type scale, spacing, radii, and shadows. It keeps the marketing site and the app feeling like one company.
* **Per-surface component layers.** The marketing site gets persuasion components (hero, pricing, testimonials, FAQ, CTA); the app gets dense workhorse UI (data tables, stat tiles, forms, filters). They are built separately on the shared token layer.
* **Themeable from day one.** Tokens are defined as variables, with the Sequence Bridge brand as just one theme. The marketing site and the agency app use the brand theme.
* **Client themes live in the app.** Each dental practice's landing page is generated by the platform with that practice's own logo and colors. Those per-client token files live in `app/themes/`, not in `internal/design/` — tenant landing pages are a platform feature, not marketing content.

## Surfaces

1. **Marketing site** (`marketing/`) — sells Sequence Bridge to dental practices. Static, deploys independently of the app.
2. **Agency app** (`app/`) — the multi-tenant platform: booking engine, SMS sequences, lead DB, per-client metrics dashboard.
3. **Tenant landing pages** — conversion pages for each client practice, generated per-practice from platform data and themed per client. Served by the app.
